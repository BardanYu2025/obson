# 第一批实验 · 同样的 768 维怎样保留历史

**第一件可做的事是把原始月份行情传到 AutoDL，运行一次预检。** 它会核文件、生成共同输入，让 P2 和 P3 各做一次真正的三任务更新，保存再加载，在同一根历史栏上复核读数。正式训练从各自的共同种子重新初始化。预检成功或失败都会在下载目录留下可移走的包。

这次问同样容量的状态，给可核实摘要留 160 维是否值得（F05），以及历史回读、遮挡补全和当前描述怎样在同一步训练（F01）。两个独立模型、两个配对种子都在本目录。主指标看留出行情的报价和相邻涨跌，也要保护最近价格、影线、量仓和当前描述。设计基线为 62cb466，中间没有前代权重。真实模型在 AutoDL CUDA 运行。Git 传代码和数据身份，原行情由使用者上传。

## 上传和拉取

默认上传目录如下。保留目录层级。时间统一用源文件的上海分钟开栏时间。

~~~text
/root/autodl-tmp/tqdata_2015/
  month_contracts/bars/<品种>/*.parquet    原始月份合约
  main/<品种>.parquet                    只读分钟时钟
  mapping/<品种>.csv                     只读交易日期
~~~

共同清单已放在 configs/snapshot.json.gz。完整快照有 2,382 份月份文件、44 个品种。主连价格、指数、旧模型、电脑上的资格缓存均不参与输入。SHA256、行数、文件长度和时间边界随读取一起核验。外层多套目录时，把 --data-root 指向直接包含 month_contracts、main 和 mapping 的一层。CPU 准备阶段另外需要数据盘存放从原始行情可再生的缓存。

新机器可执行下列命令。已有这个分支的干净检出，在仓库根运行 git pull --ff-only 即可。使用能运行 CUDA 12.8 版 PyTorch 的 Linux 镜像和 Python 3.11 或 3.12。安装脚本在本实验的 .venv 内安装固定版本；已有完全匹配的环境也可通过 BABEL_PYTHON 指定解释器。[PyTorch 2.8 的官方 CUDA 安装表](https://pytorch.org/get-started/previous-versions/#v280)

~~~bash
cd /root/autodl-tmp
git clone --single-branch -b codex/babel-next https://github.com/BardanYu2025/obson.git
cd obson
EXP=experiments/20261127_state_allocation_v1
bash "$EXP/scripts/install.sh"
bash "$EXP/scripts/autodl.sh" preflight --data-root /root/autodl-tmp/tqdata_2015
~~~

**默认 preflight 可以直接吃完整原始快照。** 初次会生成 /root/autodl-tmp/babel_state_v1 下的分片、抽样表、训练尺度和 coverage.json。之后检查两套完整宽度模型的参数数、同一步梯度、显存和保存恢复。预检的参数和 Adam 状态单独导出。成功的设备回执在缓存的 preflight.json，预填运行卡在 study.proposed.json。只想先核上传文件，命令的 preflight 可改为 prepare。缓存构建中断后重跑同一命令，可校验并复用已完整发布的分片。缺文件时错误会给出缺失路径样例。身份不同的数据使用另一个 --cache。

## 数据与真值

每个日历位置来自同一月份合约。按已见证的交易段排网格，段内缺分钟保留空位，日盘短尾栏保留实际跨度，历史夜盘缺少确切闭市依据时只接纳已闭合的整格。严格前收链仅接纳连续分钟和同品种时钟、交易日期共同见证的日间休息；真实开盘跳空保留。输出以 C_t 为锚。缺口前有来源真值的栏照常评分，另记到当前价是否能由可见价比链连通。暂定的时段和单位只用于来源单位的工程预检。

每次取最多 256/128/64/64 个已闭合的 1/5/15/60 分钟位置。每栏有九项数值、十八个可见和人工依赖位、一个尺度后备位，另有八项时间上下文和周期身份。每栏之前 64 项同周期收益估波动，预热最多再需要 65 个边界收盘。先分区，再清除跨区输入、预热和标签。2016–2023 年拟合，2024 年验证，2025 年至 2026-09-12 03:00 的分钟起点（含）供开发。IF、SA、lh、sn、OI 一律排除出拟合。此版本对最终时间和预留品种只计算样本资格；独立确认按选定用途单独签发。

三个样本池按共同的品种、完整合约、非空年月、端点分布对各自资格作条件化。成交和起末持仓按字段区分真实零与未知量。全部 18 项描述要求至少 257 个价格相接的收盘和 256 根合格的量仓。按训练池固定种子抽 1,024 个回读端点、1,024 个描述端点，拟合波动后备、特征及目标变换、分块量仓尺度和摘要给学习头的标准化。尺度写入缓存和完整包。持仓差尺度采用非零绝对差的中位数，下限一手。历史报价变换按相应周期拟合。训练集无有效分块的周期关闭其显式摘要。

## 本次训练到底比较什么

| 模块 | 执行口径 |
|---|---|
| 编码器 E | 六层、宽 768、12 个 64 维头、前馈宽 3072。12 项区间关系经过每层独立的 12→32→12 网络产生有界偏置。深层可读同视图的第一层 Value。同刻闭合的不同周期可以互读。市场位置看不到端点位置。 |
| 公开状态 | P2 保存 768 个学习数。P3 保存 32 块的四项摘要和有效位，再接 608 个学习数。两者都占 3,072 字节 FP32。摘要从共同 FP32 输入反算；决定物理校正的是保存的原坐标。 |
| 历史读头 D | 十维地址进入四个串联的条件仿射残差块，一个七项读出。P3 对有效过去块的 16 根作价格正交投影、成交非负定和投影和持仓边界校正，再取回被问的栏。已给的当前收盘只作锚。直接读数在固定尺度反算，非负量用绝对值，价格对数和影长上限 20，量仓的 log1p 上限 32。物理变换、投影及损失差分用 FP64。 |
| 描述读头 A | 768→128→18。覆盖 16、64、256 分钟，每个期限六项。后续拟合的 A′ 从冻结状态从头学习。 |
| 同一步训练 | 32 份回读、16 份填空、16 份完整描述。三类按各自均值以 1、0.25、0.10 合并。一个物理微批一个端点，累积后 E、D、A 分别裁剪一次，再更新一次 AdamW。遮挡从两段各 8 根原分钟开始，重算受影响的粗栏、前收、波动尺度、质量位和 P3 摘要。 |
| 样本与损失 | 同种子两组用相同初始共有参数、相同端点、查询、片段和曝光次数。完整回读每端点抽 64 个过去查询并枚举当前闭合栏。字段分母由整张合法查询表求出，重复抽到的栏保留次数。缺字段、内容组和过去/当前分支只在同层有支持的兄弟间重分权重。 |
| 更新与选择 | 从头训练 P2、P3 各 42、43。AdamW 峰值 2×10⁻⁴，5% 预热后余弦降到 10%，三个模块各裁剪到范数 1。主权重取固定 N 的 last；按 2024 年验证 R 保存补充 best。预检权重不进入实验。 |

单套模型的 E/D/A 分别有 42,610,308、2,107,911 和 100,754 个可学习参数。两套总数相同。P3 为校正解码同块兄弟查询的额外成本单独统计。每次更新记录实际样本、三项损失、各模块裁剪前梯度范数、实际字段曝光和展开量。设备预检另测三任务加权梯度的内积矩阵及它们与实际参数位移的内积。

## 正式矩阵与继续运行

实际使用范围和可接受误差先于候选成绩锁定。工程预检用来源单位即可。正式比较使用按历史生效日期核实的范围，源文件整个窗口须落入同一条记录。范围文件列出品种、日期、历史时段、成交与持仓各自的计量依据、对应换算倍数及合约当时的选取依据。字段格式见 configs/scope.example.json。只有一部分品种能核实，就列入那一部分并公布覆盖。使用已签范围时，第一次就对它直接预检，可以省去完整来源快照的预检。

~~~bash
EXP=experiments/20261127_state_allocation_v1
CACHE=/root/autodl-tmp/babel_state_study
bash "$EXP/scripts/autodl.sh" preflight --data-root /root/autodl-tmp/tqdata_2015 --scope /root/autodl-tmp/babel_scope.json --cache "$CACHE"
~~~

根据设备回执和用途，在生成的 study.proposed.json 中定下运行预算、报价/形态/量仓/各类描述的物理误差上限、独立市场周和刷新时延要求、近零分母的绝对处置。源码随附的 1,000 次主更新与每套 12 GPU 小时是预算草案，生效数值以看任何候选成绩前锁定的同一张卡为准。拟合冻结读头的样本数和更新数也在这张卡上。lock 绑定数据、尺度、代码和双模型 CUDA 预检 SHA。同一缓存只能锁一张正式卡。首次预检后的提交号在 preflight.json 中；后续执行固定到该 Git 提交。

~~~bash
bash "$EXP/scripts/autodl.sh" lock --cache "$CACHE" --card "$CACHE/study.proposed.json"
bash "$EXP/scripts/autodl.sh" matrix --cache "$CACHE"
bash "$EXP/scripts/autodl.sh" frozen --cache "$CACHE"
~~~

matrix 依指定次序执行四个 run，跳过已完成的正常运行，恢复已有断点。单独启动、恢复或重做开发评测的命令如下。--run 接收缓存的 runs 目录中实际生成的子目录。主训练遇到终止信号在完整更新边界导出；异常中途只从已经完整提交的优化步恢复。恢复时核对种子、数据、卡和数值后端，加载模型、Adam、随机数及步号。采样由种子、更新数、任务和样本序号确定，学习率由已完成的步数确定。

~~~bash
bash "$EXP/scripts/autodl.sh" train --arm P2 --seed 42 --cache "$CACHE"
bash "$EXP/scripts/autodl.sh" resume --arm P2 --seed 42 --cache "$CACHE"
ls "$CACHE/runs"
bash "$EXP/scripts/autodl.sh" evaluate --cache "$CACHE" --run "$RUN" --split development
bash "$EXP/scripts/autodl.sh" export --cache "$CACHE" --run "$RUN"
~~~

## 怎么读结果

完整验证遍历固定端点的全部合法查询。记录收盘及相邻变化的标准化平方误差 R、校正前后、共同有效块未写入的 14 个价格方向 R⊥、原始 OHLC 误差、按周期与近中远分组、价位是否连通、64 分钟方向、简单参照和固定遮挡误差。18 项给出联合训练头 A 的误差。每条开发记录可定位来源、分钟和市场周。模型全部训练结束后，frozen 用相同的训练缓存与种子 314 拟合七个新描述头，计算其开发集 U，另作六个未教过的极值顺序岭回归。两个 PCA 对照共用训练数据的嵌套主轴，分别用 768、608 维；后者带相同 160 个摘要与固定校正。按日历槽、字段和有效样本分别拟合两个线性历史读出。冻结读头、训练尺度、PCA 轴与真实逐样本输出随包导出。

本版训练和开发数据能支持两套方案的直接比较。只有历史绝对精度、当前描述和成本均满足预定用途，才进入独立确认。P3 替换 P2 还要求 R 至少改善 5%、两配对种子方向一致，并保护最近 16 分钟、当前实体、影线、量仓、U 与 R⊥。同摘要且同描述的反事实配对、联合市场时间块置信界、条件性同规格历史读头、最终留出只确认一次及交付复核仍按路线在相应阶段完成。程序输出开发成绩，不自动宣布哪套模型可交付。

## 保存、离机复核与还原

每个训练 run 保存独立的 best/last 引用、真实权重、优化器、随机状态、学习率步号与样本轨迹。每次发布新断点先原子写入完整文件及 SHA，再切换索引。正常结束和异常都向 /root/autodl-tmp/download 写唯一命名的 tar.gz 与同名 .json 校验回执。包中有完整实验源码、配置、依赖、运行环境、统计、数据身份和运行资产。大行情可由上传的同 SHA 原数据重建。先下载包及其同名回执再做离机验证。

~~~bash
bash "$EXP/scripts/autodl.sh" verify-package --package "$PACKAGE"
bash "$EXP/scripts/autodl.sh" restore --package "$PACKAGE" --to "$RESTORED"
~~~

restore 在新目录解包，逐文件复核大小与 SHA。换 AutoDL 实例时，在固定 Git 提交按原数据和范围重建缓存，保留同一份正式卡、preflight.json、study.lock.json。可从训练包 run/run.json 的 study 恢复相同的卡，run/preflight.json 带原预检回执。将恢复出的 run 放入新缓存的 runs 下同名位置，再执行 resume。成功生成 GPU 端文件与取得用户离机保存的回执分别登记。

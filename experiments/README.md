# 每个实验独立，发布后不改

一个目录对应一个明确问题及其匹配对照。例如现行方案的两种状态分配和成对种子使用同一实验版本，每次运行写独立的 run 目录，共用已冻结的比较协议。

```text
experiments/YYYYMMDD_question_v1/
├── README.md          前因、假设、训练说明、完整启动/导出、接受/停止与限制
├── experiment.json    ID、任务、状态、来源/前身、入口与数据身份
├── configs/           本轮所有臂/seed/预算/选择/数值配置
├── src/               本轮model、data、loss、train、evaluate代码
├── scripts/           本轮启动、恢复、打包脚本
├── requirements.lock  本轮固定依赖；发布时补环境/设备回执
├── tests/             本轮因果、损失、坐标、恢复等检查
├── release.json       发布快照SHA；不再改写
├── reports/<run_id>/  轻量报告，只追加；不覆盖原包/评价
└── runs/<run_id>/     权重、优化器和缓存；忽略Git，另作离机备份
```

`_template`只有结构和未就绪标记，没有可运行训练代码。复制模板后使用新ID，不能把模板当已完成实验。数据审计类实验的模型/神经训练项为不适用，不伪造占位模型。

- 新假设、新模型/损失/训练/评测配方必须新目录；未发布的同一实验草稿允许在自己的目录内完善。
- 发布或开始执行前封存。冻结后的小修复也用新版本，例如`..._v2`；记录`predecessor`、改动原因、受影响结论，旧目录保留。
- 同一已冻结配置的seed、合法断点恢复、预定控制臂是新run，不是新实验代码。改变科学配置就是新版本。
- 禁止从兄弟实验、旧`src/obson`或外部可变研究脚本导入/执行。需要复用就复制最小文件并登记来源哈希；以后修改只影响新副本。
- 外部Python库依赖固定；大数据和只读参照权重按清单/SHA定位，不在多个目录重复存放。内部链接不能指向兄弟目录。
- `release.json`绑定本轮所有源码、配置、测试、说明和依赖；原报告另列校验。新的报告可追加，已有报告字节不能改。纠错报告新run或新文件注明取代对象。
- `tools/`仅放治理工具，不承载可变共享模型、特征、损失或科学评价；检查器变化不能改变已封存实验的数值逻辑。

发布前流程：完善README及完整配置 → 本地合成/隔离检查 → 锁定协议 → 生成release → 检查并推送 → AutoDL同提交预检 → 正式运行。真实运行版本、数据身份和环境写入run清单。完整备份与独立目录干净恢复仍必需。

```bash
# 只在本实验真正就绪后封存；这里的ID是格式示例，不可直接执行
python3 tools/experiment_guard.py --seal YYYYMMDD_question_v1
python3 tools/experiment_guard.py --base HEAD
```

检查器覆盖目录、常见跨实验导入、符号链接、发布哈希和相对Git基线的冻结文件变更。它不证明任意动态代码没有逃逸、不证明环境可恢复、更不证明模型有效；发布审查和干净环境预检负责补足这些部分。GitHub分支保护不是本工具能自动保证的事。

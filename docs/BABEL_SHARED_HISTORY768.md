# Shared History768：在保留历史信息的同时学习共同内容

2026-09-30。探索性表示学习对照，真实训练和评价待AutoDL。本轮不追求100%还原，也不将趋势规则直接作为编码器训练标签。问题是：同一段已经发生的行情，在不同上下文、不同周期中，能否从各自的bar状态读出更一致而不塌缩的共同内容，并让原768维状态更可复用？

## 为什么现在做，和过去有什么区别

[活动权重实验](BABEL_ACTIVITY_WEIGHT768_REVIEW.md)改善了价格重建，但用途增益未共同成立，削弱活动监督还带来活动回读代价；不再扫权重。[旧跨周期实验](BABEL_CROSS_PERIOD768_REVIEW.md)主要约束解码后的价格变化，同周期重叠实验也主要比较解码结果。它们没有证明跨周期方向无效，也没有证明将整个768维状态拉近合理。

本轮保留联合重建，以新辅助读取模块从单个状态读取指定的共同历史区间，再比较这些内容向量。该模块只用于训练和诊断，部署仍可取原768维编码状态。没有将768维永久降成64维，也不把两个128根、实际时间跨度不同的完整窗口强制等同。

辅助模块改进本身不算表示升级。只有原768维状态的固定用途读出也改善、价格和活动信息保持，才记录表示候选。查询区间分数通过只能支持本协议内的一致性；不能单独证明读出了该区间的全部信息或完全排除了窗口级趋势捷径。

## 三组，两种子，同预算

起点固定为已完成`babel_activity_weight768`的`a030_s42/e100_best.pt`、`a030_s43/e100_best.pt`，源验证选中100/99轮。这是保留价量联合监督的研究起点，不是宣称上轮0.3已经获得全面用途升级。每种子各组编码器／原查询头／新辅助头初值相同，Adam重置，保留来源哈希和验证回放。

| 组 | 同周期辅助梯度到编码器 | 15→30辅助梯度到编码器 | 辅助读取模块自身训练 |
|---|---|---|---|
| control | 否 | 否 | 两项都训练 |
| within | 是 | 否 | 两项都训练 |
| cross | 是 | 是 | 两项都训练 |

因此主变量是辅助梯度能否改变编码表示；control并非不训练新头。三组输入、重建目标、参数量和数据曝光相同。保留768维／4层／8头／FFN3072及原28输入，原历史查询头仍是4个192维槽位、两层4头交叉注意力；冻结旧PCA解码器，原局部诊断头在detach状态上训练。

各100轮、4800组三视图／14400窗口曝光每轮、有效batch128、38步每轮，共600轮。原活动实验为4789组；本轮改为偶数4800并对相同合约／查询几何的不同时间成对采样。三组共享这一改变；本轮control相对旧源改善不能单归因为辅助约束。各epoch有放回抽取几何分层（概率按层内样本数），层内取两个不同端点；记录实际不同三元组数和采样指纹，不声称每轮覆盖全部训练窗口。

固定100轮是一次有限探索预算，不是充分收敛证明。全部六组结束即收束，不自动追加轮数、扩辅助宽度／权重／周期网格或替换交付接口。

## 共同历史怎样确定

复用原始OHLCV/OI核验过的同合约、同收盘时刻的周期链接。交易时段和短bar会破坏简单整数比映射，所以完全按已核验链接处理，不能用“24根30分钟必然等于48根15分钟”的bar索引换算。

每个三元组含较早细周期A、当前细周期B、同一已收盘时间的粗周期C。B中的共同细周期索引，在A中加位移；相对A末端的回看距离反而更小。每个共同close-to-close区间都必须严格早于A、B、C末端，不包含各视图当前bar。此约束训练的是共有历史，较晚B已观察到的额外上下文仍由原重建任务保留；没有为较早bar输入未来行情。

- 训练：粗周期索引边界103..115内至少4条有效链接；同周期位移1／16；跨周期辅助只用15→30。15→60样本仍参与原三视图重建和同周期辅助。
- 研究：另固定粗周期边界99..111、位移8，评价15→30及未用于跨周期辅助的30→60；15→60附报。两个范围有重叠，是新查询几何／位移，不是假称独立新行情。
- 内容是**多个经核验区间的集合**，可能有时段缺口；不是无缺口的连续时间段，也不等于相同bar数量。

有效训练池8896行。固定评价配对之后，test训练／留出几何分别2196／1884行，cross_research分别970／880行；留出15→30、30→60为test1332／484、cross616／186。启训前验证每主要组合至少50行、5周、5合约，锁定选择和来源指纹。训练分层内奇数行可被采样，固定评价的奇数尾行会排除；故8024条固定训练配对清单不是8896条可采样池大小。

## 辅助模块与实际损失

状态沿用原训练集固定均值／尺度标准化。新读取模块：768→192内容变换，区间两个端点的回看距离除127，经`2→192→192`MLP与sigmoid产生门控；门控乘内容后投影192→64，各有效区间取平均。输入只有单个状态、区间年龄和mask，没有目标价格、原bar、时间戳或合约编码。原768状态内部和原历史解码通路不变；64维仅为辅助通路的瓶颈，不能称作额外64维持久记忆。

主重建算术沿用0.3原配方：

```
0.4 path + 0.2 change1 + 0.1 body + 0.3 activity
+ 1.0 coarse_structure + 0.25 detached_local
```

辅助每对：`MSE + variance_penalty + 0.04 covariance_penalty`，同周期及跨周期两项之和乘0.10。受[VICReg](https://arxiv.org/abs/2105.04906)的方差／协方差正则启发，但本实现先在“同合约、同查询几何、不同历史时刻”的每对中去均值，再跨完整有效batch计算；这是本项目变体，不冒称原算法的直接复现或保证不塌缩。方差期望标准差至少1，数值稳定项1e-4；协方差非对角平方和除64。

这使单靠合约／几何输出固定向量无法满足方差约束。每对两个端点的eligibility及位移必须相同，两个时刻不同。跨周期有效数不足两个完整时间对时该项为0；正常训练池15→30占绝大多数，日志可核查辅助方差与损失。

编码器／局部诊断／原查询头／辅助头四个独立AdamW和裁剪组，峰值LR分别3e-5／3e-5／3e-4／3e-4，5轮warmup后cosine，各组梯度范数裁剪1。辅助头梯度不能通过共享裁剪分母改变control的原查询梯度。

方差／协方差必须对完整有效batch计算，不能把micro当统计batch。实现先分micro计算并缓存四路内容向量，得到完整batch辅助导数，再重放micro进行原重建及辅助导数反传；两遍均使用相同梯度开启的前向路径，缓存一致性检查后才更新。无dropout；合成测试将不同micro的完整参数梯度与直接完整batch反向逐项比较。额外一次编码前向对三组都存在，但实际反向工作仍有差别；报告实测时间，不宣称严格等GPU小时。

## 选模、评价、停止

保留上轮与活动权重无关的价格验证规则：近期64/128同末端过去16根路径与最远65..127结构按相对第0轮的较差者、均值、早轮次选best；价格查询／近期／远处最多退化5%，上下文路径差最多10%，第0轮回退。辅助分数、研究集合、用途标签不选编码器，不调超参。48/80/112仍不用于训练查询位置。

六组best+last共12权重先全部锁定，再对**原768维状态**训练13个线性用途读出、每目标原5档正则，共780候选，只有原验证集选正则。原raw3584／PCA768／current28、起点状态读出回放，不使用新辅助向量代替原状态。用途是历史方向／波动等描述，不是未来涨跌交易预测；它们不反向训练编码器。

原信息与用途共744检查：within对control、cross对within，cross用途还须优于control，综合用途误差至少改善5%；相对直接对照和起点保护近期／远处价格、查询分项、活动、方向／波动、当前七字段，沿用上轮5%／10%边界。近期价格增益单独报告，不是表示候选的额外必要条件。原绝对用途协议继续输出，相对改善不能冒充全面绝对通过。

共同内容另有48检查：

- 与同合约、同查询几何但不同时间的配对交换对照相比，报告`正确配对距离 / 交换距离`。防止所有样本相同或只认合约／位置。
- 去配对均值后的平均标准差≥0.1、有效秩≥8、交换距离>1e-8，且距离比<0.8；这些是事前诊断下限，不证明保留全部信息。
- 在留出查询几何中，within同周期距离比相对control改善至少10%；cross跨周期距离比相对within改善至少10%，同周期比最多退化5%。两个研究集合、两个种子、best+last及15→30／30→60均报告并要求共同通过。
- 时间对可跨自然周，故该距离比用完整合约为聚类单位，2000次bootstrap，每次重算分子与分母；至少50行、5合约。原信息指标沿用周级配对区间。

只有用途增益、信息／活动保留及共同内容检查全满足，才记`shared_representation_candidate`，仍不自动晋升。否则记无确认升级，分开报告优化未适应、塌缩、仅辅助头改善、信息取舍。固定矩阵后结合证据决定终止该配置或另立核心假设，不自动继续训练。这是重复研究集、共享预训练下的两种子微调，区间未作多重比较校正；不是独立最终确认。

## AutoDL命令和交付

```bash
cd /root/autodl-tmp/obson
git pull --ff-only origin features/babel
mkdir -p logs
nohup bash scripts/babel_shared_history768_autodl.sh all > logs/babel_shared_history768.log 2>&1 &
tail -f logs/babel_shared_history768.log
```

默认两worker并行、micro16组三视图、有效batch128。上轮六组约5小时53分；本轮增加一次编码前向和共同区间评价，先按8–12小时安排，环境／争用会改变时长，前几轮日志才可修正。单worker ETA不含排队和末尾评价。启动前检查原权重／源码／数据／原评分和零更新实际反向，动态估算磁盘、Adam和并行显存；内存估算仍不等于正式CUDA已验证。

不足时可以`BABEL_SHARED_HISTORY_JOBS=1`使用同输出恢复；micro是实验配置，改为8须同时设新的`BABEL_SHARED_HISTORY_RUN`和`BABEL_SHARED_HISTORY_LOG`。不要边运行边改代码。中断确认旧进程退出后同命令续跑（日志用`>>`保留前次记录），恢复Adam／RNG和已完成epoch。全部worker完成后若仅评价中断：

```bash

```

# Babel 实验设计、代码审查与结论要求

用户要求：在数据、架构、训练方式的拓展中大胆实验，但保持专业严谨，不能再次将有限预算筛选结果扩大为方向性否定。本文件与BABEL_RESEARCH_GOAL.md共同作为每轮工作的检查依据。

## 开始前：问题、对照与结论边界

- 写清本轮要解决的表示缺口、依据、主变量、对照组和结束后能回答的问题；标明探索筛选、预算扩展或最终确认阶段。
- 核对模型来源、预训练历史、数据端点、参数量、优化步数、样本曝光量、训练轮数及算力。相同轮数不自动代表相同计算预算或充分适应；已有特征的预训练优势必须披露。
- 数据/架构/训练目标的改动分别归因；多因素实验要有相应对照。新方案可以大胆试，但不能只给新方案或只给基线更有利的调参机会。
- 预先声明选模、保留门槛、主指标、次指标及未达标处理。不同候选集和选模规则分开报告，不能看测试结果后切换规则挑赢家。
- 明确训练预算的依据和验证曲线诊断；固定轮数只说明预算，不能充当收敛证明。充分训练、预算匹配和初始化公平是不同问题。

## 提交前：代码与验证

- 检查每项特征/目标的时间可用性、归一化来源、合约和分区边界、缺失掩码；不以零值替代缺失监督。
- 检查损失的实际梯度路径、尺度、分母和权重；确认宣称冻结的模块未更新，新增监督确实到达目标模块。
- 同时审查名义状态维数和有效信息通路：记录编码器末端内部宽度、升/降维投影的秩上界，以及向量到decoder多位置展开之前的最窄入口。不得用256→512升维宣称获得512维独立信息，或把512→256重建路径与PCA512称为严格同容量。参数匹配、有效容量匹配和相同输出shape须分别说明。
- 检查续训是否保留优化器、学习率、绝对epoch、随机状态与来源；以测试验证，不能只凭配置名称认定恢复成功。
- 检查checkpoint选择、epoch0/失败回退、完成状态和导出内容。未合格候选必须明确标记，不得把训练完成写成实验成功。
- 针对风险编写有意义的合成测试与回归检查。正式训练及神经读出拟合在AutoDL；本地不进行优化器更新。
- 完成一次区别于实现过程的复核：从结论回查指标、指标回查选模、选模回查代码和数据来源。自动测试通过不等于科学设计成立，自查也不冒称独立同行评审。
- 交付时写清验证范围和未覆盖项；本地测试不能冒充真实GPU运行验证。

## 收到报告后：证据与决策

- 先验证实际完成情况、训练来源、实际选中轮次、预算和验证曲线，再读取测试排名。
- 区分“该配置下观察到”“跨种子有支持”“具备升级条件”“仍待充分训练/独立留出确认”。未显著改善不等于方向无效，读出失败不等于信息不存在。
- 检查指标改善是否来自复制当前输入、损失尺度变化、均值收缩、初始模型回退或不同样本集合。
- 共享预训练的微调种子不冒称独立预训练复现；反复使用的研究测试集不冒称最终独立泛化验证。
- 所有预先声明的种子、失败和代价都报告；不以平均值掩盖某个种子的保留失败。
- 对未达标结果先定位数据、实现、优化、预算或评价限制，再决定补验、停止该配置或更换架构。不得默认把加层、加特征、加新模块作为下一步。
- 结论更正须写回阶段台账，保留更正原因，避免下一轮沿用已经撤回的判断。

# 原解码器同目标对照：一次零训练澄清

## 为什么做

此前把“原全局头、原局部头、新查询头”的成绩混在一起解释，容易造成“128根能重建，80根就不能”的误解。已有结果不支持这个结论。

编码器在所有bar位置共享参数，但原全局128槽位解码器主要接受末端监督，局部16根头接受抽样位置监督。参数共享不等于监督完全一致。新查询头也不是每个位置各建一个头，而是另一种共享读出结构。

本次不修改模型、不训练新头、不拟合统计或用途读出，只用已交付的control600两种子回答一个边界清楚的问题：**现有原全局解码器能否直接用于中途状态，并在相同历史目标上保留原局部头的效果？**

## 两组对照

1. **同一状态、同一目标，比较两个原头。** 原128根输入前向一次，取第32/48/64/80/96/112/128根状态。每个状态同时送入原全局解码器与原局部头，均评分该bar之前16根历史，不包含当前bar。目标、mask、尺度、样本顺序完全相同。只在同一位置比较两个头；不同位置对应不同市场片段，不能直接比较绝对误差来判断上下文长短优劣。
2. **同一结束时刻、同一目标，改变直接上下文。** 从同一窗口右侧取32/64/80/128根输入，重算末端状态，仍读取原末端之前相同16根。每种长度分别报告两个原头，不选最优长度、不拟合适配器。

原全局头输出固定128槽位。此次沿用原窗口位置的解释：前缀p的历史读取槽位p−17至p−2（零基索引），以槽位p−18的预测价格作锚点。解码器并未在本轮获得长度或位置条件。**这是一种事前固定的直接复用假设，不是已经证明的中途槽位语义。** 失败只能否定这一直接复用方式，不能证明embedding没有信息。短上下文同样使用其输入起点对应槽位0的约定，不在研究集上尝试并挑选多种槽位映射。

预测转换只用模型自己预测的锚点，不提供真实行情作为解码捷径。真实锚点只用于构造评分目标。原全局前缀误差作为诊断，mask排除当前bar与其后全部槽位。

缩短输入保留原缓存中的因果EMA等特征；绝对位置索引也从0重新开始。因此这组比较同时改变直接上下文和位置，不能单独归因给位置编码，也不代表彻底删除更早历史信息。

## 来源与评价

- 来源：`checkpoints/babel_control600_v2` 已认证bundle，seed42/43原control600权重与原配套头。不用上轮joint或新查询头。
- 两份既有研究集：test984窗、cross_research453窗；不称为全新独立测试。逐行清单沿用原交付来源。
- 4个模型/数据组合，各11个场景，batch64。全程eval、无梯度；权重签名前后相同。
- 严格验证原交付文件及上游数据/代码身份；既有65份绑定源码不改。保留原Torch/NumPy版本与运行数值设置。
- 每组先回放原局部头7个位置，以及末端原全局完整/近期误差。数值不符保存诊断并失败，不放宽已有回放协议。
- 使用原物理转换、原局部统计及原逐样本指标；完整路径误差沿用CPU float64评分。
- 直接复用判据：两种子、两数据集、7位置均满足主误差不劣于原局部头5%，path/body/activity/change1不劣于10%，按原周级配对区间上界≤0、至少50窗/5周判断。共140项，只是这一读出复用边界，不是模型准确率或研究总目标。
- 短上下文与128上下文按同一头、同一目标配对，输出24项主误差区间，仅作诊断，不设选模门槛。

## 退出与主线

一次运行结束，不自动晋升、不因失败追加训练，也不要求所有重建细节100%还原。它澄清此前混淆的比较，不是又一轮重建优化实验，也尚未实现“各位置同目标训练”。

主线仍是有用的因果bar状态表示。下一项核心设计保留“同一物理历史区间的跨分辨率共同内容”问题：区分共享宏观信息与尺度独有细节，不能强行拉齐完整向量。当前对照不检验这一假设，历史跨周期失败也不等于它被否定。

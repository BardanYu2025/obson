# AutoDL磁盘清理

2026-09-27。当前主线保留`babel_control600_v2`，下一核心实验尚未启动。旧实验之间存在递归来源校验，不能按日期或目录编号直接删除checkpoint。

## 容器进程权限修复

首次远端执行在初始进程检查读取`/proc/68669/fd/0`时遇到PermissionError；此时尚未生成清理计划，也未删除文件。容器内即便使用root，部分其他进程的描述符仍可能不可读。

已修正：无待删文件的初始检查只读进程命令行，不遍历fd；正式清理阶段仍拦截Babel进程及可见的待删文件占用，但对不可读的fd/目录记录受限PID并继续检查其他可读项。fd检查是补充性的尽力检查，不宣称可证明所有不可见进程都没打开待删文件；命令行本身不可读则仍停止清理。权限限制会显示在终端，并写入清理收据的`process_checks`。模型依赖保护、哈希、best保留与删除范围不变，不修改容器权限。

## 一条执行命令

```bash
cd /root/autodl-tmp/obson && git pull --ff-only origin features/babel && PYTHONPATH=src python -u -m obson.babel.storage_cleanup --apply
```

去掉`--apply`只预览，不删除。这个入口在AutoDL运行；本地不执行真实文件删除。

## 清理边界

1. 先完整验证当前control600交付及其旧依赖，用来源元数据中的路径及验证期间实际读取的文件收集保护目录。当前模型及所有这些祖先实验**整目录保护**，而不是仅保留best文件。
2. 对保护范围外、具有`completion.json: status=complete`的Babel实验，只删除同时被完成记录绑定、且同目录存在哈希匹配`best.pt`的`last.pt`。这是恢复训练用的模型/优化器快照；所有`best.pt`、读出、统计、缓存、日志及报告保留。未完成或无法确认来源的实验跳过。
3. 删除`/root/autodl-tmp/download/babel*_reports.tar.gz`中与[本地下载清单](BABEL_DOWNLOADED_REPORTS.json)SHA256完全匹配的报告包。清单收录实际读取校验过的46份下载副本；同名但内容不同的包不删除。原始数据压缩包、模型包及其他文件不在范围内。
4. 执行前拒绝命令行可识别的Babel进程或可见描述符中已打开的待删文件；命令行不可读则停止，fd权限限制按上面的规则记录。逐项检查内容、路径、inode及时间未改变，拒绝符号链接及路径逃逸。先写入清理清单，再删除。源校验失败时不开始删除；过程中失败保留已删除清单，停止后续删除。
5. 清理前后再次核验当前来源。记录保存为`logs/babel_cleanup_<时间戳>.json`，包含候选、跳过原因、受保护目录、文件哈希与删除进度。重复运行会跳过已删除文件。

**被清理的非主线实验不再支持原样断点续训，其旧的全文件completion校验也会报告last缺失；这是明确放弃的能力。** 原完成记录保留供追溯，清理收据说明哪些文件被主动移除。保留下来的best仍可用于后续显式设计的权重迁移，不应直接重新运行被清理实验的旧`all`命令。当前control600依赖链不会发生这种变化。

这次不移动模型、不重写旧manifest、不删除原始行情，也不关闭来源校验。实际可释放空间取决于远端现存文件；命令会先列出候选和预计回收量，完成后显示剩余空间。硬链接/文件系统共享块及外部进程写入会影响实际回收值，因此不提前承诺固定GiB。

## 工程验证

16项合成文件系统测试覆盖：预览无删除、主线保护、保留best、已下载包匹配、未知包保留、缺少完成记录/绑定文件跳过、路径或内容变化拒绝、符号链接、运行中进程/打开文件阻止、来源校验失败、删除中断收据与重复执行，以及无目标时不扫fd、描述符/目录权限受限、同一进程其他可见占用仍阻止、不可读命令行停止和受限检查写入收据。仅操作测试临时文件，不触碰本地实际checkpoint或下载包；实际容器复跑待确认。

本次清理工具不修改模型结构或训练目标。下一核心改动继续围绕bar相对坐标与一致监督设计，不能用磁盘清理当作研究推进或训练已经开始的证据。

# History Query768：让每个bar用同一套方式读回历史

2026-09-26。状态：实现已准备，真实训练和收益评价待AutoDL。起点为已验证的 `babel_control600_v2`；原交付512与control600研究接口均保留。

## 启动校验修复（2026-09-26）

首次远端启动在训练前报 `bundle/control_s42_best.pt` 指纹不匹配。根因是新入口误用 `dual_state.verify_files`：该旧函数只允许直接子文件，因目录深度拒绝了合法bundle路径，尚未实际比较该权重的SHA256。不能据此诊断文件损坏。

新实验改用支持相对嵌套目录的校验器，仍逐文件比对原SHA256，并拒绝绝对路径、`..`及逃出根目录的符号链接；原62份绑定模块与交付包不改。补齐交付来源嵌套入口、缺失/篡改/路径逃逸和已完成实验嵌套文件复验的测试。训练尚未开始，拉取修复后可直接重跑原命令，不需要重新生成control600。

## 核心问题

研究目标仍是有用的因果bar表示。当前末端通过固定PCA基底读回127根历史，中途位置另用小头读16根；监督范围、坐标与读出通道不同。原局部头适配收益很小，值得改变这个结构，而不是继续只调它的训练轮数。

这轮增加共享历史查询解码器：给它某根已收盘bar的768维状态，再指定“回看第几根”，输出对应的历史价格与活动信息。多个距离并行输出；不是自回归，不预测未来，不依赖先前生成的bar。更强解码器能否读取原有信息，与新任务能否改善编码器，必须分开回答。

## 结构与价格坐标

- 原编码器保持128窗口、28输入特征、768维、4层Transformer、8头、FFN3072。保留完整PathInput包装器、float64统计buffer、开关及投影；从已验证的bundle严格恢复。
- 原全局PCA解码器保持冻结，原局部头仍存在。原目标和0.10同周期共同历史一致性保留；不恢复已关闭的0.10跨周期约束。
- 新解码器仅接收**一个bar状态及相对历史距离**。使用原训练集拟合的状态均值/尺度固定标准化，768→768投影后拆为4个192维记忆token；没有额外历史输入。
- 相对距离的固定正弦编码经过线性投影，以两层cross-attention查询记忆token。每层宽192、4头、FFN384、无dropout。没有查询之间的self-attention，因此单独问某个距离和同时问多个距离含义相同。
- 输出7项：历史收盘路径、实体、5项成交/持仓活动。距离1..127，只监督该状态真实可见的历史；不重建当前bar或未来bar。前缀32只能监督前31根，前缀128监督前127根。

历史收盘目标为 `100 × log(C历史 / C当前已收盘)`。当前close用于定义标签/展示坐标，不作为解码器额外输入。原y缓存末行被掩码清零，必须用前一根close加当前已观察的gap/body恢复其坐标，不能把缓存的0当作价格。前缀小于128用该位置已观察的close。

价格训练尺度为 `sqrt(历史距离) × 原训练集1bar变化尺度`；不拟合新的行情统计，也不把长距离累计变化都强行压到1bar尺度。其余字段沿用原均值/尺度。1..16、17..64、65..127三个可用年龄段等权，各段内按有效样本平均；再对查询位置等权。训练使用SmoothL1，评价使用平方误差；家族权重为path0.4、change1 0.2、body0.1、activity0.3。change1从相邻历史输出计算，不包含当前bar到age1的一步。

另按原协议评价最近16根：将新解码结果减去**它自己预测的age17 close**，转换到原局部目标坐标；不会借用真实历史锚点消除模型误差。新坐标评分和这项原坐标局部评分同时报告，不能只选更漂亮的一种。

## 一次固定矩阵

两种子42/43分别从对应control600出发，先进行50轮只训练新查询头的共同预热，固定采用最后第50轮。三组复制同一份预热结果；新头的AdamW统一重置，活跃编码器/原局部头的AdamW也统一重置。

| 组别 | 编码器/原局部头 | 新查询头 | 回答的问题 |
|---|---|---|---|
| frozen | 完全冻结control600 | 继续100轮 | 原状态已有多少信息可被更强读出利用 |
| control | 原目标继续100轮 | 用detach状态训练100轮 | 单纯追加原训练的收益 |
| joint | 原目标＋新查询监督100轮 | 训练100轮 | 新任务是否改变并改善表示 |

三个查询头都经历相同50＋100轮机会。control/joint编码器都是原600＋100轮，frozen仍是600轮；不能直接拿joint与旧600比较后把全部改善归因于新任务。新头梯度系数在所有组均为1，joint仅将**回到编码器的查询梯度**设为0.25；control为0。三个模块分别裁剪梯度范数到1。

- 使用原9909个合格训练triplet池；每轮相同4789triplet、14367视图、38次优化器更新。A/B为相差1或16根的15分钟窗口，C为同时收盘的30/60分钟窗口。所有组同样读取三视图，C仍只提供原监督和新查询监督，不加跨周期拉齐约束。
- 原局部目标沿用每窗4个训练前缀。新查询目标另取4个不同的非留出32..127前缀，并始终加入128；训练排除48/80/112。同种子三组具有相同抽样、位移与前缀计划，并逐轮保存哈希。
- 有效batch128 triplet；默认micro16，通过梯度累积实现，单次编码器实际48视图。支持micro8/16/32/64，运行中不静默改变；改变配置需新输出目录。
- AdamW峰值：encoder 1e-5/weight_decay0.01、原local 3e-5/1e-4、新query 3e-4/1e-4；5轮预热，余下cosine到峰值0.1。保留FP32原计算设置，不自行加入AMP/TF32。
- 相同样本曝光和更新次数不等于相同FLOPs，记录每轮时间、累计更新、显存峰值和尾部验证走势。

## 选择、评价与停止

只用原978个验证窗口，位置32/64/96/128。主阶段统一最小化：

`0.5 × (原验证selection / 分支第0轮原selection + 查询验证误差 / 分支第0轮查询误差)`。

分支第0轮保留为候选。旧selection仍是原定义，两个归一化分母在共同预热分叉时固定。预热固定50轮最后状态，不由研究集选择。

全部六组完成100轮并锁定best/last后，才对12份状态统一拟合13个用途读出，每项只用原5个Ridge系数，共780个候选。统计和拟合只用训练数据，系数选择只用验证数据。全部读出锁定后才访问984个原品种、453个跨品种研究窗口。两个集合此前已经反复研究，**不是新的最终留出**。

联合组成为研究候选必须同时满足：

1. 中途留出位置48/80/112的新原生查询误差、原坐标最近16根误差，相比同预算control和frozen均至少改善5%，周级配对区间上界通过；两个种子、两个研究集、best与last全部检查。
2. 新末端查询误差保留5%；中途path/body/activity/change1家族保留10%；新查询在重叠位移1/16/64的共同变化/实体/活动差异保留5%。
3. 原全局、中途局部、末端近期综合误差保留5%，原全局家族误差保留10%；原重叠差异保留5%。同时与control和原control600比较。
4. 校准后历史用途综合保留5%、方向/波动家族保留10%；当前字段NMSE≤0.1、R²≥0.8并满足原周级支持要求。
5. 原raw3584/PCA768/current28完整用途协议独立运行和报告。新查询通过不抹掉原用途未达标结论，不自动替换任何交付版本。

输出 `history_query_research_candidate` / `query_gain_with_tradeoffs` / `no_joint_query_gain`。必须逐项解释主要收益及代价，不能用总通过率决定升级。

固定矩阵结束后停止，不自动加轮数、改损失权重、扩大维度或挑某个种子。若新头仍未优化充分，只能说本预算没有解决，不能断言向量里没有信息；查看末20轮轨迹和第0轮回退。冻结组若已明显受益，可结束编码器改动，单独评估读出价值。joint只有在同结构、同新头训练预算对照中胜出，才支持新增监督对表示有增益。

## 工程约束

旧绑定源码保持不变，新实验使用新增模块；最开始校验原交付及训练血缘、权重、缓存、原验证分数和因果性。原统计与PCA基底保持固定。每个worker的 `last.pt` 是恢复权威，包含模型、最好状态、优化器、随机状态及完整历史；重启核对manifest、预算、采样、验证回放。完整预算后才写完成标记，选模锁和读出锁绑定文件哈希。

本地只运行合成前向/反向、无优化器更新的生命周期测试及合成Ridge校准；不训练或推理真实模型。37项相关检查覆盖因果/掩码/价格锚点、梯度路由与原目标一致性、micro累积、断点恢复/完整预算/第0轮回退、六组到最终报告的完整合成流程、原接口及失败导出；lint、脚本语法与62份旧绑定源码哈希检查通过。正式CUDA显存和速度尚未实测。默认jobs1/micro16面向当前12GB显卡，日志逐轮显示该worker的实测秒数与剩余时间；不能把预热速度当作整个矩阵时长。较大显存可在启动前设置jobs2，两个worker并行，但没有为当前3080Ti实测两任务峰值。

## AutoDL运行与打包

沿用原Torch/NumPy环境及完整checkpoints目录，特别是 `babel_control600_v2`、`babel_cross_period768_v2_recheck` 和来源训练缓存。无需补行情、重跑旧实验或重新导出control600。

```bash
cd /root/autodl-tmp/obson
git pull --ff-only origin features/babel
mkdir -p logs /root/autodl-tmp/download
nohup env BABEL_HISTORY_QUERY_JOBS=1 BABEL_HISTORY_QUERY_MICRO=16 \
  bash scripts/babel_history_query768_autodl.sh all \
  > logs/babel_history_query768.log 2>&1 &
tail -f logs/babel_history_query768.log
```

中断后原命令会恢复完成的轮次；不要同时启动两个相同输出任务。正常结束或报错退出都自动复制报告/日志并打包到：

`/root/autodl-tmp/download/babel_history_query768_reports.tar.gz`

手工再次导出：

```bash
cd /root/autodl-tmp/obson
bash scripts/babel_history_query768_autodl.sh export
```

回传上面一个压缩包即可。包括manifest、源码/来源哈希、预检、8个worker的历史与预算、两个选择锁、全部逐窗指标、原参考回放、固定等距样例、决策与运行日志。权重及大型数组保留在原checkpoints，不放进报告包。导出保留failed/partial状态，不把压缩包存在当作实验成功。

## 范围、现状和主线

R0v2已执行；[复核](BABEL_RECOVERY_R0_REVIEW.md)确认六份权重140个验证值与原记录完全一致。第一次R0的运行后端问题已修复。R0没有证明损失设计合理、模型已经均衡或历史训练全都正确。其真实梯度加法性诊断仍有限制。

本轮保留Macro control s42/s43 best97/94，768维、4层、8头，作为冻结研究参照，不称全局最优。实际权重主干如下，详细边/指纹仍在同名JSON：

```
control600 + 原查询头预热 → Bar Semantics uniform
 → History Structure control → Causal Pool plain（开始继承结构目标）
 → Depth四层扩展预算 → Activity Weight 0.3
 → Shared History control → Macro History control97/94
```

Shared失败辅助分支和Macro content/aligned不在该权重主干；Context没有晋升。Uniform的从头训练权重也没有进入Context，后者只借用其输入缓存。主干仍继承了结构目标和局部detach设计，不能靠“没继承失败分支”证明设计无误。

已盘点的61份旧报告对应60个运行根目录；九关键阶段做过源码/协议细查，其余51个仅盘点，不能宣称全史审完。台账逐条保留原复核结论及限制；没有证据要求全部旧矩阵重跑。本次目的仍是因果价量/持仓状态的信息保留与用途，重建误差不能单独作为胜利。

## 训练前的零更新资格

- 按已核实SHA恢复同一Macro两个种子、原查询和训练集尺度，锁定历史源码、原始数据身份、分区/合约边界。R0已通过部分复用结果，不重复全部原始读取；新运行所加载资产仍必须校验。
- 后端固定为Context原MHA fastpath关闭、TF32关闭、线程4；按R0规则复放基线24项验证值，不放宽阈值。源无选中同一步Adam，统一新Adam，称受控适配。
- E2：固定训练批同一次前向，分别保存实际总反向与各项梯度、参数名顺序、残差和有效dtype。先保持既有1e-6绝对/2e-5相对数值核对，失败导出诊断、停止，不以事后放宽消除错误。另记录梯度裁剪前后量；小批比例不直接用来自动调权。
- RS局部头冻结参数并设eval，沿用源权重、旧过去16根目标和train-only尺度。核对有可追溯的源头权重、真实标签及选中状态；**不能新建随机头补齐缺失权重**。将该头在两个种子的native验证端点/中途位置误差，与只用train计算的固定均值预测比较：每种子两类位置的局部primary都必须低于均值对照；不通过则停止RS并报告该头未获得资格，不临时预热或换头。这个最低资格不是证明头已充分拟合。
- RS四组使用相同源局部头；它不加入优化器。零更新检查baseline与原Context Q+S相同，其他组只出现预定梯度差；目标/mask/状态相同。同步验证未知模式、错误形状、未来扰动、局部头可训练等失败路径。

## R1：只检验学习率，不替结构问题背书

两个种子各5轮，均从原Macro best和新Adam开始。prefix单视图、batch128/micro8、五位置、采样流、合并裁剪、目标、衰减与旧Context prefix一致。

唯一训练改动是固定LR幅度：s42编码器3.066380815642346e-6/查询3.0663808156423456e-5；s43编码器3.2648704606900738e-6/查询3.2648704606900735e-5。复用旧高LR前5轮作参照前，核对起点、采样和目标签名；不能核对则停止，不自动新增高LR任务。

第5轮必须是实际更新权重；两种子所有24项full/native×端点/中途保留值均不超过源的110%，且无非有限数，才允许RS。epoch0回退不能过关。失败就报告，不扫第三档LR。通过只表明五轮稳定，不说明60轮稳定，更没有解决远端偏置或局部监督。

## RS：两项结构疑点的2×2对照

实现见`src/obson/babel/recovery_objectives.py`，目前只是损失组件，**尚无可开跑脚本**。

| 组 | 目标 | 直接比较 |
|---|---|---|
| baseline | 原查询Q + 1.0远端结构S | 同期适配对照 |
| without_remote | Q | 相对baseline：移除额外S的有限效应 |
| with_local | Q + S + 0.25局部L | 相对baseline：额外L回传编码器的有限效应 |
| without_remote_with_local | Q + 0.25L | 相对without_remote检验L；相对with_local检验S；披露交互 |

Q保持0.4路径/0.2变化/0.1实体/0.3活动及原可用年龄段平均；L是原局部16根价格和活动联合目标，不是纯价格任务。两因子均不改变输入、位置/样本采样、原查询架构或标签定义。四组从同种子的同一源开始，使用R1预定LR、新Adam、同衰减/裁剪、batch128/micro8、原prefix五位置和相同30轮采样流。局部头都冻结，不给某组额外头适配预算。

移除S或增加L会改变总梯度和裁剪因子；这属于该目标干预在同一优化器配方下的实际效应。必须记录，不能把结果归因于容量竞争或唯一数学机制。固定局部头还会偏向源坐标；不把接口保留自动解释成信息量增加。

### 选模、报告和验收

- 保持源epoch0候选和原24项验证保护；沿Context原minimax选择，仅由val选模型。best/固定30轮last全保存、全披露。只有epoch0合格时，写“没有更新候选通过”，不能算修复成功。
- 四组在相同full/native输入、同物理目标、端点/留出中途位置评价近/中/远价格、活动、结构。另报告价格物理单位MAE、变化RMSE、P50/P90/P99，避免平均总loss遮盖大误差。近端不能跨不同坐标/标签支持比较。
- 针对S1/S2，近段价格至少5%改善、其他原24项不超过10%损伤；须同时对同期对照和源报告。按原合约/时间成组的配对区间方法分别披露两种子、两研究集、best/last，区间不支持则未确认，不把点均值改善叫成功。四组和全部因子比较均披露，不能只挑研究成绩好的组合。
- 编码器用途仍用原13目标、每个相同5档alpha机会；train拟合、val选参，研究评价前锁定模型及读头。要称表示升级，还需对同期对照的用途至少5%增益及原保留门槛；只改善局部头兼容性不够。研究集已反复使用，不称最终独立泛化证明。
- 任何一组有取舍就标取舍；两个因素在不同背景效果不同就报告交互，不能只凭“组合最好”说两个猜测都成立。不因loss继续下降追加轮数。全部未达标则停止此四组配方，保留原Macro，不加层、不扫权重。

## R2及其他问题如何继续，不丢分支

R2暂缓，原A/B/C仍保留：A前缀+原支持，B完整128输入+逐张量等同A的目标/mask，C同B输入+全部历史目标。B−A是包括位置/路径锚点变化在内的上下文编码策略；C−B仍同时改变标签支持和段权重。不得把该三组说成已经分别隔离了全部因素。

S4已有dense_matched，复用其结果；S5已有Grounded内容绑定/错查询资格与原头诊断，失败配方不重包再跑；S6接口与信息分离仍开放，在确需判断候选时另立同目标等预算读取对照。Depth、Pool、Activity的解释限定见逐项台账，不因改正结论口径就自动整套重训。

从头全位置、跨分辨率共同内容、未来状态外推分支保留。当前均不是执行队列，也未被近端问题证明无效。最终独立留出必须在研究方案冻结后再用于验收。

# Position Supervision768：先检验每个位置是否应该承担历史监督

2026-10-01。用户要求将自己的猜测纳入计划、逐步推进。本轮是新增的第一阶段；未来状态外推计划保留为后续阶段，不同时改变编码器监督与预测任务。状态：代码已准备，真实CUDA训练/数值与资源检验待AutoDL。

## 要验证的猜测

“如果训练开始就让1～128各位置都计算损失，会不会让不同bar状态、近期和远处历史更均衡？”

已有多位置监督曾改善中间状态，并非从未试过。当前来源训练是每视图随机四个中间位置＋固定末端，query损失已有近/中/远分段，不能将这些已有机制重新宣传为新方案。

这次先检验**从相同已训练来源继续训练时，监督密度及位置权重的作用**。不是从随机初始化重训的结论；也不是完整滚动128上下文对齐，更不是未来预测。只有这一有限矩阵支持明确问题，才决定后续核心改动。

## 来源和不变项

- 沿用Macro History control验证best：s42=97轮，s43=94轮；严格读取完成凭证、checkpoint和全部来源链，不按本任务重选旧权重。
- 768维、4层、8头、FFN3072、原非线性查询头、28维因果特征和原单合约输入不变。输入原始数据仍由来源指向`/root/autodl-tmp/data/contracts`。
- 每个种子的三组从相同编码器、查询头与原局部头出发，统一重置优化器。全部组编码器/查询头继续训练，局部头只读detach状态；原PCA全局解码器冻结。
- 原训练合格三视图队列、4800组三视图/轮、batch128、38更新/轮、采样流、LR、原分区与原价量目标不变。
- 原查询：0.4路径＋0.2单步变化＋0.1实体＋0.3历史活动；另有1.0粗结构损失与0.25不回传编码器的局部头损失。本轮不改变这些任务系数。
- 原当前bar未纳入历史重建，继续用既有当前字段协议评估；不能称本轮加入了当前bar自重建。

## 三组×两种子，各60轮

| 组 | 位置与权重 | 解释 |
|---|---|---|
| sampled | 原32..127合格位置中抽4个，各0.2；128固定0.2 | 同预算普通续训对照 |
| dense_matched | 原合格中间位置全部读出，总权重0.8均分；128为0.2 | 精确积分原抽样目标的期望权重，主要改变估计噪声/解码计算量 |
| dense_all | 2..128共127位置等权，各1/127 | 用户全位置猜测的可回读历史版本；同时改变短前缀覆盖和位置权重 |

原合格中间位置排除48/80/112；dense_matched仍排除，dense_all包括。三组分别每视图5/94/127个query context。dense_all相对dense_matched不是“只改变采样密度”的单因素对照，结论必须注明覆盖与权重一起变化。

短前缀没有远处历史目标；加入这些前缀并等权平均，会改变近远任务的实际贡献，因此不能预先称为“自动平衡”。

第1个位置没有窗口内已观察的过去，因此没有这个任务的合法历史目标；不伪造127个padding标签，也不引入当前输入复制损失。因果特征可能携带窗口前预热信息，但没有授权本轮去构造另一种窗口外监督。

第p个状态在窗口内仍只有p根上下文，全位置监督不等于每根状态看过完整128根。位置48/80/112在dense_all里已经训练过，报告旧schema中的`held`只代表兼容的“原保留位置集合”，**不能再宣称本轮对这些位置作零曝光泛化验证**。研究行情分区保持不变，但这些分区已重复使用，不是新独立留出。

总预算六组×60=360 worker-epoch，各2280更新、864000视图；三种方式的decoder计算量不同，不能称等FLOPs。60轮是从同一强来源出发的有限继续训练，不证明充分收敛；不拿它和历史模型总训练轮数直接排名。

## 避免密集解码占满显存

每个microbatch只做一次编码器前向，将状态复制为可求导叶子。查询头按4个位置分块解码，各块的query参数梯度与状态梯度累积，最后把完整状态梯度一次回传编码器。块间不执行优化器更新，encoder梯度没有截断。

每块只解码其中实际可能出现的历史年龄，再在掩码外补零供原评分函数处理；原头query间无相互注意力，这种裁剪不改变有效读取语义。测试比较完整目标、分块、不同microbatch的损失与梯度，并与旧sampled损失直接比较。

micro默认8，单worker；允许`JOBS=2`时运行真实无更新梯度预检，按可用显存决定一组或两组。batch128和有效更新预算不变，不盲目占满显存。配置改变必须使用新输出目录，避免未记录地改变断点语义。

## 选模与评价

- 统一沿用原验证集near/far minimax选模，第0轮保留。query_price/near_price/far最多比共同初始值增加5%，gap最多10%；在合格候选中最小化near/far相对初值的较差者，同分再看均值，仍同分保留更早轮次。
- 验证位置仍32/64/96/128；研究集各位置曲线不进入选模。六组best/last锁定后，再拟合相同13项原用途读出、每项原五档alpha，共780闭式候选；无新神经头网格。
- 原价格、活动、当前字段、重叠稳定性、raw/PCA/current用途协议继续评价。直接回放来源报告，数值错误必须保存诊断并停止。
- 新增每个位置2..128的真实历史价格/变化/实体/活动/粗结构误差曲线，保存逐窗口数组以复算。第2位置没有单步差分对；短前缀不具备完整远处粗块，缺少支持不能解释为零误差。
- 位置增益主比较为32..127的等权价格误差：dense_matched对sampled；dense_all对sampled及dense_matched。要求至少5%配对周区间增益，两种子、两研究集、best/last均检查。2..31新加入位置单独展示，不用容易的极短历史稀释主指标。
- 用途升级要求原用途至少5%增益且位置增益成立，同时保留原价量信息；原用途综合最多退化5%、各任务族/当前历史字段等沿用原5%/10%边界。dense_all须同时保护sampled、dense_matched和源；dense_matched须保护sampled和源。
- 可分别得出“位置改善但用途未升级”“近期有收益但有取舍”“完整研究候选”结论。原绝对用途门槛仍另报；不存在自动替换默认模型。反复研究数据与未校正区间的边界继续披露。

## 工程与有限决策

恢复已有包装输入层，不重新初始化decoder；代码、数据、来源、起始query/encoder签名、每轮位置曝光、优化器/RNG恢复、best/last和报告锁定均记录。完成凭证存在时仍复核真实文件，不能只见文件名便跳过校验。

真实CUDA前置：来源回放、因果性、每组无更新梯度/显存预检、实际模型与优化器尺寸推导磁盘需求。前两轮耗时给本worker ETA；不同模式query量不同，不用sampled耗时直接估整批。原模型/数据不删除。失败保存报告并打包，不把退出0当科研成功。

1. 若dense_matched优于sampled且保留通过，支持密集计算在本预算下的作用；仍非等算力收益。
2. 若dense_all相对两个对照进一步改善且保护通过，支持新增位置覆盖/重加权这一组合；不能单因归因于某一项。
3. 若近期好而远期/活动损坏，确认取舍仍在；不自动扫权重或加层。
4. 若改善仅来自普通续训，按对照如实记录，不包装成全位置训练突破。
5. 若验证末端还改善，记录预算限制；不自动加训。下一阶段才决定完整上下文端点训练或冻结状态外推，不让两种核心变化混在一轮里。

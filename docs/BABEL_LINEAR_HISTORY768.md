# Linear History768：要求主状态支持简单历史读取

2026-10-01。一次有限的主训练方式对照；真实训练和结果待AutoDL。

## 这次要回答的问题

最近几轮已经证明，状态里有可读出的历史信息，但重建改善没有稳定转化成原线性用途改善。Macro History还揭示，编码器和解码器一起适配后，固定旧读取器可能明显失配。不能把这种失配都说成信息丢失，也不能把约束旧接口的成功说成新增记忆。

下一步检验一个不同的核心假设：**把主历史解码器限制为线性读取，是否会促使非线性编码器把历史信息组织成更容易复用的状态？** 这是改变主任务的信息读取方式；不再增加共同内容头、对齐项或辅助损失，也不把方向／波动规则反向喂给编码器。

旧共享回读实验中MLP曾优于ridge，这是需要认真保留的反向证据：现成状态未必适合简单共享读取。本轮检验能否通过主训练改变这种组织方式，不预设非线性解码器没有价值。

这是待检验假设，不是已确认瓶颈。线性解码器可能牺牲重建能力，也可能并不改善方向／波动用途；一次失败不能证明信息不存在或所有线性化都无效。线性读出也没有唯一固定768维坐标，任意可逆线性变换仍可由读取权重补偿，因此不承诺不同周期整向量相同。

## 与过去方案的差别及理论边界

- 早期PCA实验确实已经使用过固定线性逆变换，且plain组直接监督真实历史；不能把线性解码包装成首次尝试。本轮区别在于：当前768维／4层起点、共享的相对年龄与多prefix任务、可训练的线性读取权重，以及同预算普通续训／冻结编码器对照。旧固定窗口坐标成绩不能直接回答这个新任务。
- 过去的用途线性探针冻结编码器；本轮让**主历史任务**的线性读出梯度更新编码器，同时保留真正冻结编码器的对照。
- 历史查询头／固定宏观读取器都包含非线性处理；本轮直接替换主查询头，不叠加新支路。
- 先前池化／加深实验改变编码器，本轮保持768维、4层、8头、输入处理与上下文不变。

[线性自编码器研究](https://proceedings.neurips.cc/paper/2020/hash/4dd9cec1c21bc54eecb53786a2c5fa09-Abstract.html)讨论了线性自编码器的子空间、正则和优化；本轮编码器仍非线性、存在多prefix mask及加权Huber／结构损失，不能套用“等价PCA”的结论。[VICReg官方线性评价协议](https://github.com/facebookresearch/vicreg#linear-evaluation)说明冻结表示后检查线性读取是一种评价方式；它不保证线性历史重建训练必然使本项目用途提升。方案推断主要来自本项目证据，论文只用于厘清概念边界。

## 来源和模型

固定本轮已完成`babel_macro_history768`的两个`control`验证best，选中97／94轮；选择理由是上轮已确定保留的普通续训研究参照，而非挑本轮研究分数。读取原完整来源链、源码绑定和不可变完成清单；核验原价量查询与相同末端上下文评分，核验因果性后才训练。

编码器保持28输入、768维、4层／8头／FFN3072。价量归一化、PathInput、合约边界、因果attention、原训练／验证／研究队列全部继承，不拼连续合约，也不改变数据切分。

线性读取形式：

```
u = (z_t - train_mean) / train_scale
prediction(age) = W_age @ u + b_age, age = 1..127
```

每个年龄输出原7个历史字段；总参数`127 × 7 × (768 + 1) = 683641`。没有激活、交叉注意力、额外状态、原始bar旁路；年龄仅索引对应权重。可以读取任意整数回看距离1..127，也可一次取全部年龄。年龄0／未来不允许；真实可用历史之外的标签严格mask，不把padding当作零行情监督。

这不是把每个bar改成889维持久状态。持久状态仍768维，889只是训练时全部127个年龄×7个输出。当前bar七字段仍按原独立用途协议检验。线性头和原头参数量不同，是研究变量的一部分，不宣称等参数／等计算比较。

## 有限三组、两种子

先分别对原解码器、线性解码器进行**30轮冻结编码器适配**。两种子、两类头，合计四次。原头从已训权重开始，线性头从零权重／零偏置开始。两类头得到相同训练样本、学习率、损失和更新机会，但已有知识不同；这不是从零训练的架构排名。

适配采用固定第30轮，不用研究集选头；记录验证过程和优化曲线。即使线性适配质量较弱，也不根据研究结果追加轮次或择优更换配置。30轮不是充分收敛保证，联合训练另有100轮；若新头后续仍学不好，结论只能限定于本预算。

| 主组 | 编码器 | 主历史解码器 | 作用 |
|---|---|---|---|
| native_joint | 更新 | 原非线性头，继续更新 | 正常继续训练的对照 |
| linear_frozen | 冻结 | 线性头，继续更新 | 只让读取器学习，信息本身不变 |
| linear_joint | 更新 | 线性头，继续更新 | 检验主任务线性化能否改善状态 |

线性两组从**相同适配权重**分叉。三组编码器起点逐权重指纹相同；冻结组最终必须仍相同。原头的适配也冻结编码器，防止给普通续训额外编码器训练优势。

主阶段各100轮，每轮4800组三视图、有效batch128、38步；种子42／43。三组同种子的样本、shift、query位置、曝光和LR流相同。复用上一轮经核验的9277行可采样训练池，跨周期视图只参加原价量重建，没有跨周期一致性损失。适配与主阶段使用不同且预声明的随机流。

总计720个worker-epoch、27360次优化更新，其中适配4560步，主阶段22800步。冻结组没有编码器Adam／反向，线性头计算更少，不能称等GPU小时；分别报告耗时、显存、LR、采样指纹、梯度范数和权重变化。

## 损失与选模

沿用原目标，无新增权重：

```
0.4 历史价格路径 + 0.2 相邻变化 + 0.1 实体 + 0.3 成交/持仓活动
+ 1.0 远处粗结构 + 0.25 detached局部诊断
```

活动输入和活动重建监督都保留。局部诊断头在detach状态训练，不反向影响编码器；旧PCA解码器冻结。原随机训练prefix及保留位置48／80／112协议不变，历史查询始终只读取对应prefix的一根状态。

适配和主阶段各自重置Adam；同阶段LR均为5轮warmup+cosine，编码器峰值3e-5、局部头3e-5、主查询头3e-4，各参数组独立裁剪1。micro只拆计算，完整batch的样本损失按实际batch大小累加后更新，不改变曝光或损失定义。

主阶段仍按近期／远处价格相对本组适配后第0轮的较差者、均值、早轮次选best，并保护价格／上下文差、第0轮回退。不同头的初始误差不同，**本组验证下降不构成跨头胜利**；最终必须与普通续训及来源的绝对错误比较。适配阶段记录的best仅供诊断，分叉始终用last。

## 评价与成功标准

先锁定六组的best/last，共12权重，再做原13目标×5档正则，共780个线性用途候选；只在原训练集拟合、验证集选正则。用途评估仍读取原768状态，不读解码器输出，不给用途目标向编码器反传。

两个种子×两个研究集合×best/last全部报告。线性联合组需：

1. 原状态用途综合误差相对native_joint、linear_frozen均至少降低5%，且配对区间支持。
2. 对native_joint、linear_frozen和训练来源，保护近期／远处价格结构、历史查询分项、方向／波动用途及成交／持仓信息，沿用原5%／10%范围。
3. 保护与native_joint相比的共同历史稳定性；当前7字段继续要求原R²／标准化误差门槛。

共512项预声明比较（16用途增益、8价格增益诊断、440其他保留、48活动保留）。价格增益单独记录，不是用途候选的额外必要条件。原raw3584／PCA768／current28绝对用途协议继续保留；通过相对候选标准不冒充绝对全通过，也不自动部署替换。

只有原重建变好而用途未改善，记录重建收益；只有线性头变好而冻结状态用途相同，不记表示进步；用途好但价格／活动显著取舍，明确报告取舍。只在这一个矩阵中作结论，不自动追加层数、头数、正则或解码器网格。重复使用的研究集、共享预训练和未校正多重比较仍是局限，不宣称独立最终确认或预测交易能力。
